# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Biblioteca Zapata is a bilingual (Spanish/English) Hugo static site cataloguing ~2,154 books and publications from Luis Zapata's personal library. Content is sourced from Zotero and deployed to GitHub Pages.

## Build & Dev Commands

```bash
# Local development server
hugo server

# Production build
hugo --minify
npx pagefind --site public    # full-text search index (required after build)

# Full CI build matches deploy.yml workflow
hugo --minify && npx pagefind --site public
```

Hugo version: v0.125.6+ (extended). No package.json, Makefile, or JS build toolchain — plain CSS/JS only.

## Data Pipeline

Scripts run manually from project root. Requires `pip3 install pyyaml anthropic`.

```bash
# 1. Import Zotero CSV → Hugo content files
python3 scripts/import-csv.py --csv zlibrary.csv --output content/catalogue

# 2. Optimize cover images (requires ImageMagick)
bash scripts/optimize-images.sh "/source/Photos" static/covers

# 3. Build subject map from raw Zotero tags → canonical categories
python3 scripts/build-subject-map.py        # outputs data/subject_map.yaml

# 4. Apply subject map to all content files
python3 scripts/remap-subjects.py           # rewrites front matter in-place

# 5. (Optional) AI subject classification via Claude Haiku
export ANTHROPIC_API_KEY=...
python3 scripts/classify-subjects.py        # outputs data/llm_subjects.yaml
```

## Architecture

### Content model

Each book is `content/catalogue/<ZOTERO_KEY>.md` with YAML front matter: `title`, `authors`, `year`, `decade`, `publishers`, `place`, `languages`, `item_types`, `series`, `subjects`, `cover`, `zotero_key`, plus optional `isbn`, `oclc`, `doi`, `pages`, `edition`, `featured`.

Hugo taxonomies: `authors`, `publishers`, `subjects`, `languages`, `item_types`, `series`.

### Rendering pipeline

The catalogue list page is **JavaScript-first**: `catalogue/list.html` loads `index.json` (generated by `catalogue/list.json` template), and `assets/js/catalogue.js` handles faceted filtering, text search, pagination (24/page), and grid/table view toggle. Hugo's paginator is only a `<noscript>` fallback.

Templates: `layouts/_default/baseof.html` → partials (`header.html`, `footer.html`, `book-card.html`, `metadata-table.html`, `search.html`) → page-specific blocks (`index.html`, `catalogue/list.html`, `catalogue/single.html`, `_default/list.html`, `taxonomy/list.html`).

No external theme — all templates are in `layouts/`.

### i18n & subject translation

Subjects are stored in **English** in content files and translated at render time via `i18n/en.toml` and `i18n/es.toml` using computed keys:

```
subj_{{ subject | replaceRE " " "_" | replaceRE "&" "and" | replaceRE "'" "" }}
```

Language names use `lang_*` prefix keys. Both i18n files contain ~201 subject translations, ~14 language translations, and ~30 UI strings.

## Key Conventions

- **Zotero keys**: uppercase in filenames (`224TXDP8.md`), lowercase in cover paths (`covers/224txdp8.jpg`)
- **Subjects always in English** in `.md` files — never store translated subjects in content
- **No writer-name subjects** — do not create subject categories named after writers (e.g., "Jorge Luis Borges", "Julio Cortázar"). Books are already linked to authors via the `authors` taxonomy; duplicating them as subjects is redundant.
- **Languages stored as full names** (`"Français"`, `"Español"`), not ISO codes
- **Adding or removing a subject category** requires updates in three places simultaneously: both `i18n/*.toml` files and `VALID_CATEGORIES` in `scripts/classify-subjects.py`. Also check `scripts/build-subject-map.py` for classification rules. Never modify catalogue files without ensuring the corresponding i18n and script entries exist.
- **Verify author nationality before assigning national literature subjects** — do not assume nationality from the title language or place of publication. A Spanish translation published in Mexico of a Chinese author is "Chinese Literature", not "Mexican Literature" or "Japanese Literature".
- **Taxonomy sorting uses translated labels** — taxonomy listing templates collect terms into a slice with their translated labels, then sort by label. This ensures alphabetical order works correctly in both languages. Do not use `.Data.Terms.Alphabetical` directly for display when translations are involved.
- **Collection stats** (`totalItems`, `totalAuthors`, `yearRange`) in `config/_default/params.toml` must be updated manually when the collection changes
- **`featured: true`** in front matter marks items for homepage display
- **URL structure**: `/es/` and `/en/` subdirectories (`defaultContentLanguageInSubdir = true`)
